# Day12 시작 안내 - 누가 이 폴더를 쓰나요?

이 폴더는 **어제(Day11) 완료 상태가 미리 세팅된 공용 시작점**입니다. 어제 어디까지 갔는지에 따라 아래 두 갈래 중 하나로 시작합니다.

## 갈래 1 - 어제 배포까지 끝난 분

**이 폴더가 필요 없습니다.** 어제 쓰던 내 폴더에서 그대로 시작합니다.

1. 어제 폴더를 VS Code로 열고 `claude` -> `/start`
2. `day12-kit.md`(이 폴더 안에 있음)만 열어 두고, 키트의 문장을 복사해 씁니다

## 갈래 2 - 어제 막혔던 분 (500·404·안 열림)

이 폴더로 갈아타면 5분 안에 오늘 출발선에 섭니다. 어제 것을 고치느라 오전을 쓰지 않아도 됩니다.

1. **폴더 열기** - 이 폴더(day12-starter)를 VS Code로 엽니다 (File > Open Folder)
2. **환경 확인** - 터미널에서 `claude` 실행 -> `/start` -> `[환경OK]` 한 줄 확인
3. **표와 정책** - Supabase 대시보드 -> 내 프로젝트 -> SQL Editor -> 이 폴더의 `setup.sql` 내용을 통째로 붙여넣고 Run 한 번 (어제 이미 표를 만든 분도 그대로 실행해도 안전합니다)
4. **열쇠 연결** - 두 값(SUPABASE_URL, SUPABASE_ANON_KEY)이 Vercel에 이미 있으면 건너뜁니다. 없거나 모르면: Supabase 프로젝트 Settings > API에서 두 값을 확인 -> Vercel 프로젝트 Settings > Environment Variables에 입력
5. **배포** - `claude`에서 `/deploy` -> 나온 주소를 #실습공유에 올립니다

여기까지 되면 어제 완료 상태와 같습니다. 이제 `day12-kit.md`의 0번(아침 확인)부터 똑같이 진행합니다.

## 이 폴더에 미리 되어 있는 것

- `setup.sql` - 표 + 넣기 정책(어제) + **읽기 정책(오늘 몫)** 이 한 파일에 있습니다. 갈래 2로 이 파일을 실행했다면 키트 3번(읽기 문 열기)은 "이미 됨"이니 확인만 하고 넘어갑니다
- `CLAUDE.md` - 오늘 만들 파일 3개(list.html, detail.html, api/list.js)가 파일 규칙에 미리 등록돼 있습니다. 키트 2번(규칙 넓히기)도 "이미 됨" - 에이전트에게 "파일 규칙 읽어줘"라고 확인만 해 봅니다
- 새 컬럼을 만들 때 빈 값 금지(not null)를 붙이지 않는 규칙 - 어제 여러 명이 겪은 500 에러의 예방책이 규칙에 들어 있습니다

## 오늘 만드는 것 (미리 안 만들어져 있습니다 - 실습입니다)

접수 목록 화면(list.html), 상세 페이지(detail.html), 읽기 서버(api/list.js)는 **여러분이 에이전트에게 시켜서** 만듭니다. `day12-kit.md`의 4번·5번 지시문을 쓰면 됩니다.
